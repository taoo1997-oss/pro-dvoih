# Поиск клиентов — свадебные лендинги

Два инструмента:

1. **`поиск-клиентов.html`** — один файл, ничего не устанавливать. Панель-навигатор:
   куда идти за клиентами (VK, Telegram-чаты невест, Профи.ру, YouDo), где искать
   партнёров (+ шаблон письма и мини-CRM), как смотреть конкурентов, что настроить
   у себя (Директ, контент). Впишите город и ключевые слова — ссылки перестроятся.
   Открывается на телефоне, можно переслать почтой. **Начните с него.**

2. **Приложение с автосбором** (ниже) — Flask, запуск через `run.bat`. Само тянет
   свежие запросы с FL.ru, Kwork, Telegram. Полезно, но таких запросов мало —
   основной поток дадут партнёры и своя реклама (см. панель, вкладки «Партнёры»
   и «Свои каналы»).

---

## Приложение с автосбором

Локальное приложение: собирает свежие запросы заказчиков на изготовление
свадебных сайтов-приглашений с бирж и Telegram, показывает карточками, по клику
переводит на страницу запроса.

## Запуск

1. Установлен Python 3.10+.
2. Двойной клик по **`run.bat`** (он сам поставит зависимости и запустит).
   Или вручную:
   ```
   pip install -r requirements.txt
   python app.py
   ```
3. Откроется `http://127.0.0.1:5017`. Жмите **«Найти запросы»**.

Остановить — закрыть окно консоли.

## Что где ищется

| Источник | Как | Что получаем |
|----------|-----|--------------|
| **FL.ru** | RSS-ленты проектов | автоматически, разобранные карточки |
| **Kwork** | JSON со страницы «Биржа проектов» | автоматически, с бюджетом |
| **Telegram** | публичные превью каналов (`t.me/s/…`) | автоматически, если в канале включено превью |
| **Avito** | — закрыт для парсинга — | готовая ссылка на поиск по сайту |
| **Профи.ру** | — закрыт — | ссылка на категорию «создание сайтов» |
| **YouDo** | рендерится JS, ненадёжно | готовая ссылка на поиск |

Запросы именно на свадебные лендинги **редкие** — часто список «Точные
совпадения» пустой. Поэтому есть второй блок **«Похожие запросы»**: обычные
лендинги/одностраничники без слова «свадьба» — им можно предложить услуги.
И всегда — блок **«Ручной поиск на площадках»** с прямыми ссылками туда, где
объёмы больше (Авито, Профи.ру).

## Как работает отбор

1. Тексты нормализуются (нижний регистр, ё→е, снятие тегов).
2. `finder/matching.py` считает релевантность:
   - **точное** — есть и «свадьба/свадебный…», и «сайт/лендинг/приглашение…»;
   - **похожее** — есть «лендинг/одностраничник», но нет «свадьбы»;
   - **мимо** — свадебное, но про фото/видео/ведущего/платье и т.п. — отсекается.
3. Бюджет вытаскивается из поля биржи или из текста («бюджет 12000», «10 т.р.», «8к»).
4. Новизна: всё найденное пишется в `leads.db` (SQLite). При повторном поиске
   уже виденные помечаются как не-новые, новые — бейджем **НОВОЕ**.

## Настройка — `config.json`

Меняйте под себя (после правки просто снова нажмите «Найти запросы»):

- `keywords_wedding`, `keywords_site`, `keywords_negative`, `phrases_bonus` —
  словарь отбора;
- `fl_ru_feeds` — какие RSS-ленты FL.ru брать;
- `kwork_pages`, `kwork_categories` — сколько страниц Kwork и по каким категориям
  (`""` — все, `"11"` — разработка, `"13"` — дизайн);
- `telegram_channels` — список каналов (без `@`); работают только те, где
  включено веб-превью;
- `manual_links` — карточки-ссылки на Авито/Профи.ру/YouDo и т.д.

## Тесты

```
pip install pytest
python -m pytest
```

17 тестов, все офлайн (на сохранённых фикстурах в `tests/fixtures/`):
`test_matching` — нормализация, парс бюджета, корзины; `test_sources` — разбор
RSS/JSON/Telegram, сбор ошибок; `test_aggregate` — сборка, дедуп, новизна,
устойчивость к падению источника; `test_app` — HTTP-ручки Flask.

## Структура

```
app.py               Flask: UI + /api/search, /api/leads, /api/archive, /api/runs
config.json           настройки
finder/
  config.py            загрузка config.json с дефолтами
  matching.py          нормализация, парс бюджета, скоринг, корзины
  sources.py           фетчеры: fl_ru, kwork, telegram, manual_cards
  aggregate.py         run_search(): собрать → оценить → в базу → отдать UI
  store.py             SQLite: кэш лидов, «уже видел», история поисков
templates/index.html  весь фронтенд (без сборки)
leads.db              создаётся при первом поиске (в .gitignore)
tests/                pytest + фикстуры
```

## Честно про ограничения

- **Авито и Профи.ру** не парсятся автоматически — там жёсткая антибот-защита.
  По ним приложение даёт готовые ссылки на поиск (открываются в браузере).
- **Telegram** отдаёт только каналы с включённым веб-превью и только последние
  ~20 сообщений.
- Это не круглосуточный мониторинг — данные подтягиваются в момент нажатия
  «Найти запросы». Хотите регулярно — запускайте несколько раз в день.
